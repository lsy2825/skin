# 가격 지켜보기와 푸시 알림

상태: 앱 안 알림(관심·가격 알림, 4.0까지)은 그대로 동작. 서버 푸시(5.0)는 코드 + 모의 테스트만 — VAPID 키·서버 배포 없음 → BLOCKED_EXTERNAL_DEPENDENCY.

## 1. 정직한 주기

가격은 **주 1회** 모아요(월요일 + 이벤트 종료 다음 날 판단). 그래서 알림은 새 데이터가 들어온 뒤에만 가고, 어디에도 '실시간'이라고 쓰지 않아요(테스트: 알림 글에 '실시간' 없음, '수집 기준' 날짜 포함).

## 2. 이용권과 규칙

- PRICE_WATCH_7D(1C) / PRICE_WATCH_30D(3C) → 이용권 기간 동안 규칙을 만들 수 있어요(`commerce_watch_rule`: 이용권 없으면 402, 규칙 50개까지).
- 규칙 종류: `target`(목표가 이하 등장), `newlow`(지켜본 뒤 최저), `newmatch`(가격 있는 지점 수 증가), `watch`(중간값 5% 이상 변화 또는 최저 하락). 지역 선택 가능.
- 첫 실행은 기준값만 저장하고 알림 없음.

## 3. 실행 (Cron, 데이터 빌드 뒤)

- `runWatch`: 살아 있는 규칙 → 현재 데이터로 평가 → `commerce_watch_event`(규칙·변화·데이터 버전마다 한 번; 같은 데이터로 다시 돌려도 새 알림 없음).
- 푸시는 사용자당 한 번(요약), **조용한 시간**(기본 22~8시 KST) 안이면 다음 실행으로 미뤄요.
- 푸시 내용은 비어 있어요(payload 없음) — 서비스 워커가 일반 문구를 보여주고, 앱이 로그인 뒤 `GET /v1/notices`로 읽어요. 그래서 푸시 서비스는 가격·시술을 몰라요.
- VAPID(RFC 8292) ES256 JWT, aud = 푸시 서비스 origin, 12시간 만료.
- 구독 주소는 알려진 푸시 서비스(FCM, Mozilla, Windows, Apple Web Push)만 허용(사용자가 보낸 주소로 서버가 요청하므로 SSRF 방지). 404/410이면 구독 삭제, 5번 연속 실패도 삭제.

## 4. 테스트 (api 11)

이용권 없음 402 → 이용권 구매 → 규칙 → 이상한 구독 주소 거절 → 1차 실행: 알림 1·푸시 1(본문 없음, vapid 헤더) → 2차 실행: 새 알림 0 → 알림 목록 1개(수집 기준 문구) → 조용한 시간 계산(22→8 넘김) → JWT aud 확인.

## 5. 남은 일

서비스 워커의 `push` 처리(일반 문구 표시)와 앱의 구독 화면은 서버 모드에서만 의미가 있어 아직 앱에 넣지 않았어요. 서버 연결 때 추가해요.
