# Price Now 기능 감사 (참고 사이트 역분석)

기준일: 2026-10-14. 지시서 "YOONSILJANG 3.0 — PRICE NOW INTELLIGENCE EXPANSION" PART 1.
- 참고 사이트: https://price-now.price-now-cloud.workers.dev ("피부과 가격 지금")
- **브랜드·외형·코드는 가져오지 않았어요.** 화면 구조와 문구로 기능을 파악했고, 사이트의 스크립트(app.js·match.js)는 열어보지 않았어요. 윤실장 구현은 모두 새로 썼어요.

## 1. 어떻게 조사했나
| 방법 | 결과 |
|---|---|
| 이 환경에서 직접 접속(curl·브라우저) | **막힘.** 이 작업 환경의 네트워크 정책이 `*.workers.dev` 연결을 거부해요(HTTP 403 CONNECT). |
| 외부 수집 도구(Firecrawl)로 화면 받기 | 성공(3번). ① 첫 화면(JS 실행 8초 후) ② 같은 화면의 HTML 구조 ③ '정보' 화면(25초 후, 데이터를 다 받은 상태) |
| 버튼을 눌러 보기(검색 실행, 장바구니 담기, '지금 다시 확인', 알림 켜기, 설치) | **못 했어요.** 수집 도구는 페이지를 읽기만 해요. 그래서 아래 표의 "동작"은 화면 문구로 읽은 것이고, 실제로 그렇게 동작하는지는 확인하지 못했어요. |

받아 본 사실(수집 시각 2026-10-14):
- 머리말 상태 문구: 받는 중 "새 가격 확인 중…" → 다 받은 뒤 "123/123곳 · 방금 동기화"
- 진행률: "가격 받는 중… 67/123곳"(54%), "102/123곳", 설명 "받은 지점부터 바로 검색할 수 있어요."
- 지역 선택: 전국 123곳, 서울 40, 경기 34, 인천 7, 부산 6 … 제주 2(17개 시·도, 곳 수 표시)
- 브랜드 칩: 블리비·쁨·톡스앤필·리엔장(4개, 모두 켜짐)
- '포함할 가격' 칩: 체험가 포함(켜짐) · 묶음 포함 · 조건부 포함 · 부가세 포함 가격(꺼짐)
- '검색어 쓰는 법': `보톡스 50u` 모두 포함 · `-파워` 빼기 · `제오민|독일` 둘 중 하나 · `300샷` 그 숫자만(1300샷은 아님) · `1회?` 횟수가 적혀 있으면 1회만
- 자주 찾는 시술 36개. 각 버튼은 연산자를 쓴 검색어예요(예: '국산 사각턱 보톡스 50U' = `턱보톡스 50u? -파워 -자갈턱 -이중턱 -제오민 -독일 -수입 …`).
- 결과 안내: "결과는 지점마다 가장 싼 가격 하나씩, 싼 순서로 보여 줍니다." / '브랜드별 최저' 목록
- 장바구니: "여러 시술을 한 지점에서 받을 때 합계가 가장 싼 곳을 찾습니다." · '합계가 싼 지점' · 지역 선택 · **"1~3위 지금 다시 확인"** 버튼
- 알림: "최저가가 내려가거나 최저 지점이 바뀔 때 알려 드립니다." · 지켜보는 시술 · 알림 기록 · 푸시 패널
- 정보 › 가격 데이터 상태: "블리비 53/58곳 최신 · 6시간마다 새로 확인 · 가장 오래된 지점 7시간 전 · 가장 최근 14분 전"(쁨 20/25, 톡스앤필 29/34, 리엔장 6/6 · 24시간마다)
- 정보 › 어떻게 동작하나요: ① 서버가 1분마다 오래된 지점 한 곳씩 병원 사이트를 다시 읽음(6시간/24시간 안) ② 앱은 바뀐 지점만 받아 휴대폰에 저장하고 검색·비교는 휴대폰 안에서 ③ "지금 다시 확인"은 그 지점 사이트를 바로 다시 읽음, 요청 간격 때문에 기다릴 수 있음
- 고지: "부가세 10% 별도 게시가 기준 · 각 병원과 무관한 비공식 비교 · 예약 전 지점에 꼭 확인"
- 설치 안내: iPhone(Safari 공유 → 홈 화면에 추가, iOS 16.4+ 알림) / Android(⋮ → 앱 설치) + "이 기기에 설치하기" 버튼
- 이 기기: 앱으로 실행 "아니요(브라우저)" · 저장된 지점 123곳 · 저장된 가격 69,062줄 · 마지막 동기화 "방금" · (값이 "null"로 보이는 줄 1개 — 참고 사이트의 표시 오류로 보여요) · 앱 버전 2026-10-13.1 · "저장된 가격 지우고 다시 받기"

## 3. 그대로 가져오지 않은 것과 이유
| 참고 사이트 | 윤실장 | 이유 |
|---|---|---|
| 결과를 "지점마다 가장 싼 가격, 싼 순서"로 | 기본은 지역·이름순, '낮은 가격순'은 고르는 정렬 | 사용자 지시 ②(최저가 단독 강조 배제, `OBJECTIVE_DISPLAY_POLICY.md`) |
| '브랜드별 최저' + 지점 이름 | 브랜드별 지점 수·범위·중간값·조건부 수·확인일, 지점 이름은 플래그를 켤 때 | ② |
| 장바구니 '1~3위' | 사용자가 '합계 낮은순'을 고르면 '맨 위 3곳' 확인 카드(순위 문구 없음) | ② |
| "지금 다시 확인" = 병원 사이트 즉시 재수집 | 기록 보여주기 + 원본 열기 + 실제 재확인 요청(GitHub) | 재수집 서버가 없어요. 되는 척하지 않아요 |
| 6시간/24시간마다 새로 확인 | 매주 월요일 + 이벤트 종료 다음 날 | 지금 수집기의 실제 주기예요. 근거 없이 6시간을 약속하지 않아요 |
| 지점 하나씩 나눠 받기 | 파일 하나(압축 795KB) + 버전 확인 | 측정 결과와 구조 차이(`PRICE_SYNC_ARCHITECTURE.md` §2) |

## 4. 확인하지 못한 것 (추정으로 구현했다고 하지 않음)
- 실제 검색 결과의 순서·묶는 방식, 브랜드별 최저 목록의 내용(데이터를 다 받은 화면에서도 빈 목록으로 수집됨)
- '지금 다시 확인'을 눌렀을 때의 동작, 기다리는 시간, 요청 간격
- 푸시 알림이 실제로 오는지, 알림 기록에 무엇이 남는지
- 오프라인에서의 화면, 증분 동기화의 실제 방식(화면 문구 "바뀐 지점만 받아"만 확인)
- 설치 버튼이 지원하지 않는 브라우저에서 어떻게 보이는지
