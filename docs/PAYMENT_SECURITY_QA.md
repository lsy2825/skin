# 결제·지갑 보안 QA (5.1)

**모든 결과는 로컬 PostgreSQL 16 + 모의 결제사(토스·Apple·Google)로 실행한 거예요. 실제 결제사 샌드박스로는 아직 결제하지 않았어요.** 웹 결제(토스)는 공식 API 명세대로 만든 모의 서버로, Apple·Google은 검증 계약(서명·체인·필드)만 확인했어요 — 네이티브 앱이 없어 인앱 결제는 테스트하지 않았어요.

## 지시서 항목별

| 항목 | 결과 | 테스트 |
|---|---|---|
| 주문 만들기(가격 스냅샷, 클라이언트 금액 무시, 멱등) | 통과 | ledger 1, api 2 |
| 결제 시작(서버 주문 값으로 결제창) | 서버 쪽만 통과. 앱 결제창 화면은 미구현(서버 모드 닫힘) | api 1 |

| 크레딧 사용(예약→차감, 보너스 먼저) | 통과 | ledger 4, 7, api 6 |

| 요청 폭주 | 사용자당 작업 분당 20회, 21번째 429 | api 15 (메모리 기반 — O-01) |
| API 비용 남용 | 사용자 하루 AI 호출·서비스 하루 비용 한도, 비용표 없는 모델 거절 | api 13 |

## 독립 검토가 확인한 '맞는 것'

주문 행 잠금 + 주문당 결제 1건 + (결제사, 결제 ID) 유일 + 원장 멱등 키로 이중 지급 불가 / 지갑 잠금으로 지출 직렬화 / 체크 제약으로 음수 불가 / 차감·반환·만료가 작업 행을 잠그고 상태를 다시 읽음 / 22개 표 모두 RLS, `commerce_*` 함수는 anon·authenticated가 실행 불가(`has_function_privilege`로 확인) / 원장 추가 전용.
