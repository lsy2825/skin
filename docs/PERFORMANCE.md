## 해석

1. **이번에 실제로 좋아진 것은 R09 하나예요.** 느린 망에서 버전 확인이 막혀도 저장본 가격이 1.5초 안에 보여요(전: 31초). `fetchMeta`는 8초 뒤 포기하고 저장본을 계속 써요.
2. **첫 방문은 그대로예요(약 9초, 이 제한 조건에서).** 전송량 1.3MB 중 가격 데이터가 대부분이라, 이걸 줄이는 O2(홈 요약 분리)를 하지 않으면 바뀌지 않아요. 다음 단계 1순위예요.
3. **검색은 그대로예요.** 첫 검색 때 메인 스레드가 약 2초 막혀요(4배 느린 CPU 기준). O3(색인 사전 생성 또는 Worker)가 필요해요.
4. 재방문 중앙값이 91ms 늘었어요. 가장 느린 경우는 2.3초예요. 같은 조건으로 더 많이 반복해야 차이가 진짜인지 알 수 있어요. **개선이라고 주장하지 않아요.**

## O2 홈 요약 먼저 (2026-10-14)

무엇: 빌드가 `app/home.json`(홈 화면이 보여줄 수 있는 비교 키 89개의 줄을 지점 전부 — 12,324줄, gzip 171KB)을 따로 만들고, 사본이 없는 첫 방문에는 이걸 먼저 받아 홈을 그려요. data.json(gzip 1,883KB)은 home.json을 다 받자마자 이어 받고, 오면 전체로 바꿔요. 설계·무결성은 `docs/PRICE_SYNC_ARCHITECTURE.md` §2. 홈 숫자가 전체 파일과 같은지는 `tests/homedata.test.js`와 `tests/e2e/o2_home.js`(탭 9개·발견 목록, 기본·전국+부가세 포함)로 확인했어요.

조건: 위 브랜드 확대 절과 같은 도구·제한(slow4g, 3회 중앙값). 전 = `586b30e`(git worktree), 후 = O2. 원자료 `docs/evidence/perf_o2.json`.

| slow4g 첫 방문 (중앙값) | 전 | O2 1차 | **O2 최종** |
|---|---|---|---|
| 홈에 가격이 보이기까지 | 16,126ms | 6,910ms | **8,184ms** |
| 전체 가격(모든 화면이 열림)까지 | 16,132ms | 20,021ms | **17,718ms** |
| CLS | 0.000 | 0.086 | **0.000** |
| 누르기 반응 최대(INP 유사, 전체 가격 뒤 7번) | 520ms | 480ms | 624ms |
| 전송(측정 도구 값) | 2,384KB | 2,753KB | 2,753KB |

| 재방문·fast (중앙값) | 전 | O2 최종 |
|---|---|---|
| slow4g 재방문 가격 표시 | 2,759ms | 2,790ms |
| fast 첫 방문 가격 표시 | 1,043ms | 1,171ms |
| fast 재방문 가격 표시 | 853ms | 889ms |

**해석**
- 좋아진 것: 느린 망 첫 방문에서 홈 가격이 **약 8초 빨리**(−49%) 보여요.
- 나빠진 것: 모든 화면이 열리는 시점은 **약 1.6초 늦어요**(+10%). home.json을 먼저 받는 만큼 data.json이 늦게 끝나요. 1차 구현은 data.json을 앱 스크립트 뒤에 시작해서 +3.9초였고, `gate.js`가 home.json 직후 바로 시작하게 고쳐 줄였어요(대신 홈이 6.9초 → 8.2초로 늦어짐 — 같은 회선을 나눠 써서).
- CLS: 1차에선 홈 요약 중 안내 줄이 떴다 사라지며 본문이 43px 밀렸다 돌아왔어요(0.086). 진행률을 머리말 글자로 옮겨 0이 됐어요.
- 전송: 실제로 늘어난 건 **home.json 171KB(+7%)뿐**이에요. 표의 +369KB 중 나머지(죠미 대사 29KB, 글꼴 조각 5개 134KB)는 '전'에서도 받지만, 홈이 16초에야 떠서 그때는 서비스 워커가 요청을 처리해 측정 도구가 0바이트로 셌어요(`workerStart` > 0, `transferSize` 0을 확인). 이 도구의 '전송' 값은 서비스 워커가 처리한 요청을 빠뜨려요 — 비교할 때 주의.
- 누르기 반응: 520 → 624ms는 세 번 중앙값이라 차이가 진짜인지 모르겠어요(같은 조건 재방문도 472 → 560ms로 흔들림). 개선이라고도 악화라고도 주장하지 않아요. 큰 반응 지연의 원인(14MB 원본을 읽고 색인하는 일)은 O3(검색 색인/Worker) 몫이에요.
- fast 첫 방문 +128ms: home.json을 한 번 더 읽고 그리는 비용(추측). 빠른 망에선 이득이 없어요.
- 실기기 측정 아님.
