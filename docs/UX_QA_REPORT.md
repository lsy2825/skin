## 1. 검사 환경
- **브라우저:** Playwright가 띄운 Chromium(헤드리스)이에요. 실제 휴대폰이 아니에요.
- **화면 크기:** 390×844(일반 휴대폰), 320×800(작은 휴대폰). 다크 모드는 `prefers-color-scheme: dark`로 확인했어요.
- **서버:** 로컬 정적 서버(`python3 -m http.server 8766 --directory app`)에 실제 `app/data.json`(2026-10-13 수집, 118개 지점)을 썼어요.
- **서비스 워커:** 끄고 검사했어요. 네트워크 지연과 오류를 흉내 내기 위해서예요.
- **다시 돌리는 법:**
  - `node tests/e2e/ux_qa.js`: 아래 2절의 23개 검사
  - `node tests/e2e/touch_targets.js`: 터치 영역 검사
  - 단위 테스트: `node --test tests/*.test.js`
  - 비교 키 테스트: `python build2/xkeys.py`

## 3. 기능별 확인 결과 (Playwright 시나리오 t11~t14, kb3, 직접 관찰한 값)

**스마트 검색**
- "강남 슈링크 300샷 10만원 이하"를 입력하면 `area=강남&max=100000`으로 해석돼요. "문장 그대로 찾기" 링크(`nl=0`)도 있어요.
- 검색창이 비어 있으면 최근 검색(이 기기)과 인기 시술이 떠요.
  - 인기는 **파는 지점 수 기준**이에요. 실제 검색량 집계가 아니에요(5절).
- 결과가 없으면 대안을 제안해요: 필터 빼기, 전국에서 찾기, 단어 하나 빼기, 비슷한 검색어.

**필터**
- 선택한 필터 칩을 하나 지우면 결과가 6 → 93개로 늘어요. "모두 해제"도 있어요.
- 옵션마다 결과 수를 보여줘요(예: "스킨부스터 (625)"). 0개인 옵션은 고를 수 없어요.
- 숫자 칸과 슬라이더가 같은 값으로 맞춰져요(30000/50000). 최소가 최대보다 크면 빨간 안내가 뜨고, 그 값은 적용되지 않아요(`aria-invalid=true`).
- 용량·샷 칩이 있어요(슈링크: 100샷 395개, 300샷 288개 …). 조건 저장(프리셋)도 돼요.

**장바구니**
- 시술을 빼고 되돌리기. 전체 비우기 후 되돌리면 2개가 복원돼요.
- 예산 상한: 0 이하는 거부하고, 넘는 견적에는 "예산 +9,000원" 표시가 붙어요.
- 이름 바꾸기는 시트로 해요.
  - 빈 이름은 오류를 보여줘요.
  - Tab 6번 눌러도 포커스가 시트 안에 남아요.
  - 닫으면 포커스가 연 버튼("+ 새로")으로 돌아가요.
- 키보드로 담은 뒤에는 포커스가 다시 그려진 "담김 ✓" 버튼으로 돌아와요(kb3).

**비교**
- 지점 화면 ‹ ›로 같은 브랜드 다음 지점으로 가요(4/34 → 4/33).
- 즐겨찾는 지점은 시술 비교 위에 고정돼요. 가격이 없으면 "이 지점은 이 시술 가격이 없어요"라고 보여줘요.
- 지점 비교 "차이 있는 것만": 29줄 → 15줄.
- 최저가 3곳을 출처 URL과 함께 복사할 수 있어요. 지점 비교 결과도 복사돼요.

**개인화**
- 홈에 즐겨찾기(시술·지점)가 보여요.
- 지도 가운데를 "집"으로 저장하면 위치 버튼 이름이 "집"으로 바뀌고, `pc:places`에 저장돼요.

**데이터 투명성**
- 가격 오류 신고 시트가 있어요. 사유 5가지, 메모, GitHub 이슈 링크가 있고, 링크 제목·본문에 지점·상품·앱 표시가·출처·확인일이 들어가요.
- "내용 복사"로 신고해도 기기에 기록돼요(`pc:reports`). 운영 현황 화면에서 볼 수 있어요.

**회귀 검사(같은 날)**
- 단위 테스트 `node --test`: 23/23 통과
- `xkeys.py`: 90/90 통과
- 이전 E2E 시나리오 test.js, t6~t14: 모두 페이지 오류 0건

## 4. QA에서 찾아서 고친 문제
1. **키보드 흐름이 끊김**
   - 증상: 가격 범위 칸에서 Tab으로 빠져나가면, 값이 그대로여도 화면을 다시 그렸어요. 그래서 포커스가 문서 처음으로 돌아갔고, 아래 "+ 담기"까지 Tab으로 갈 수 없었어요.
   - 고침: 값이 실제로 바뀔 때만 적용해요(`app/app.js` priceTable `commit`).
2. **예전 장바구니가 저장되지 않음**
   - 증상: 예전 `pc:cart`를 메모리에서만 옮겼어요. 그래서 열 때마다 장바구니 id가 새로 생겼고, 로그인 후 서버 병합에 쓸 id가 흔들릴 수 있었어요.
   - 고침: 옮긴 결과를 한 번 저장해요(`loadCarts`). 예전 키는 지우지 않아요.
3. **다시 그리면 포커스가 사라짐**
   - 증상: 필터, 수량, 즐겨찾기처럼 화면을 다시 그리는 동작 뒤에는 키보드 포커스가 사라졌어요.
   - 고침:
     - 같은 화면이면 같은 컨트롤(이름표·순서 기준)로 포커스를 돌려놔요(`focusMark`, `focusBack`).
     - 새 화면이면 본문(`#main`)에 포커스를 줘요.
     - 시트를 연 버튼이 그사이 다시 그려졌으면, 같은 자리의 새 버튼으로 돌아가요.
4. **터치 영역이 작음**
   - 증상: '출처' 링크와 글자형 버튼은 22×18~19px, 가격 슬라이더는 높이 16px이었어요. WCAG 2.2 최소 기준은 24×24px이에요.
   - 고침: 레이아웃은 그대로 두고 누르는 영역만 넓혔어요(`.linkbtn::after`). 슬라이더는 24px로 키웠어요.
   - 재검사(`touch_targets.js`): 11개 화면에서 보이는 컨트롤 1,482개 모두, 중심에서 ±11px 지점을 눌러도 그 컨트롤이 눌려요.
     - 접힌(details) 목록 안처럼 보이지 않는 요소는 제외했어요.
     - 숨긴 체크박스는 겉으로 보이는 스위치를 누르기 때문에 제외했어요.

(그 전 개발 중에 고친 것: 비교 탭 카테고리 칩이 주소의 이전 시술로 되돌아가던 문제, 입력 중 화면이 다시 그려지던 문제, 같은 브랜드 지점 전환이 지역 밖 지점에서 숨던 문제.)

## 5. 남은 문제와 주의점
- **인기 검색어:** 서버와 이용 통계가 없어서, 파는 지점이 많은 시술을 "인기"로 보여줘요. 화면에 "인기 시술"로 적고 있지만, 사용자는 실제 검색 순위로 오해할 수 있어요. 실제 검색량은 P2예요(개인정보·서버 필요).
- **확인한 것(문제 아님):** 지점 화면에서 경주점 "주름보톡스(국산 일반형) 한정가" 2,090원이 "중간보다 111%↑"로 보여 데이터 오류인지 확인했어요.
  - 같은 이름 옵션 40줄은 모두 같은 묶음이에요.
  - 병원 표시가 분포: 800원 4곳, 900원 21곳, 990원 1곳, 1,000원 6곳, 1,900원 5곳, 2,900원 3곳.
  - 경주점은 1,900원(부가세 포함 2,090원)이고 중간값은 900원대라서, 계산이 맞아요.
- **포커스 복원 방식:** 이름표와 순서로 같은 컨트롤을 찾아요. 필터 때문에 목록 순서가 바뀌면 비슷한 위치의 다른 컨트롤로 갈 수 있어요. 버튼 자체가 사라지는 일은 없어요.
