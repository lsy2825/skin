## 1. 층
지시서는 Category → Family → Product/Device → Variant → Spec → Clinic Offer → Pricing Condition이에요. 지금 데이터에서 각 층은 이렇게 돼요.

| 층 | 무엇 | 어디서 | 예 |
|---|---|---|---|
| Category(분야) | 톡신·윤곽·필러·리프팅·부스터·피부·제모·바디·패키지·기타 | `taxonomy.py CATS` | 제모·바디 |
| Family(제품군) | 같은 시술 이름(부위별로 나눈 것 포함) | `taxonomy.py FAMILIES` 120여 개 + 이름 그대로 묶음 | 겨드랑이 제모, 사각턱 보톡스, 리쥬란 |
| Product/Device(제품·장비) | 병원이 상품명에 적은 제품·장비 이름 | `classify.js products()`(장비 9종 정규화 + `spec.js PRODUCTS` 42개) | 아포지 플러스, 젠틀맥스 프로 플러스, 제오민, 리쥬란 |
| Variant(옵션) = **비교 묶음** | 같은 제품군·같은 속성·같은 용량·같은 횟수 | 직접 만든 36개(X01~X36) + 자동 2,581개(T…) | 리쥬란 힐러 2cc, 여성 겨드랑이 제모 아포지 플러스 5회 |
| Spec(규격) | 용량·샷·유닛·부위·횟수·원산지 | 비교 묶음 속성 + `spec.js parse()`(상품명에서 읽기) | 2cc · 1회 · 국산 |
| Clinic Offer(병원 상품) | 지점이 올린 가격 한 줄 | `data.json` 가격 줄 62,404개 | 블리비 강남역점 "리쥬란힐러 2cc 체험가" |
| Pricing Condition(가격 조건) | 종류(일반·체험가·한정가·구독권·고시가)·첫 방문·요일·시간·부가세·기간 | 가격 줄의 kind·tags·vat·until | 체험가 · 첫 방문 · 부가세 별도 · ~10/17 |

### 자동 비교 묶음의 서명(signature)
`제품군 | 이름 | 속성 | 남은 낱말 | 세부(괄호·'-' 뒤) | 용량 | 횟수`

서명이 같고 3개 지점 이상이 팔면 비교 묶음이 돼요. 4.0에서 서명에 넣은 것은 다음과 같아요(`PRODUCT_AUDIT.md` F-04).
- 제모 장비 8종
- 화면에 보이는 이름에서 읽은 제모 부위
- 괄호 속 부위·성분(착색토닝, 수액)
- 개당/얼굴전체/부분(아그네스, 포텐자)
- CO2/어븀글라스(프락셀)
- LDM 분(分)
- 포텐자 펌핑 모드·팁 별도
- 외국산 = 수입

## 2. 선택 흐름 (쉬운 보기 · 자세히)
비교 화면에서 제품군을 고르면 **쉬운 보기**(기본)가 단계별로 보여줘요.
1. **종류**: 비교 묶음 이름에서 용량·횟수를 뺀 나머지(원산지·제품·장비·부위 낱말)
2. **용량·부위**: 그 종류 안의 용량·샷·유닛·부위
3. **횟수**: 1회 / N회 묶음

예시는 이래요.
- 리쥬란 → 종류(힐러·HB 플러스·아이 힐러…) → 용량(1cc·2cc…) → 횟수(1회·3회 묶음)
- 보톡스 → 부위(사각턱 보톡스 등 제품군 선택) → 종류(국산·독일산·프리미엄) → 유닛(50U·100U) → 횟수

동작 방식은 다음과 같아요.
- 단계 칩을 누르면 앞 단계의 선택을 지키면서 가장 가까운 비교 묶음으로 옮겨요.
- 같은 조건이면 파는 지점이 많은 쪽을 골라요.
- 선택지가 하나뿐인 단계는 숨겨요.

**자세히**는 예전처럼 모든 옵션을 종류별 줄로 보여줘요. 고른 보기 방식은 이 기기에 저장돼요(`pc:cmpMode`).

## 3. 비교 판정 A~J (가격 한 줄 × 비교 묶음)
지시서의 A~J를 이 앱의 데이터로 정의했어요.
- 판정은 병원이 적은 상품명·가격 종류·조건만 보고 내려요. 시술 내용을 앱이 확인한 것은 아니에요.
- 가격 근거 창 맨 위에 판정과 이유를 보여주고, 'A~J 뜻' 창에 전체 설명이 있어요.

| 판정 | 이름 | 비교 수준 | 언제 |
|---|---|---|---|
| A | 같은 시술·같은 규격 | 그대로 비교 | 묶음의 제품·용량·횟수와 상품명이 맞음 |
| B | 제품명 표기 없음 | 비교하되 확인 | 같은 묶음의 다른 줄은 제품을 적었는데 이 줄엔 없음 |
| C | 다른 제품·장비 | 비교하되 확인 | 한 묶음에 제품·장비가 둘 이상(예: X35 겨드랑이 제모의 아포지·클라리티·젠틀맥스) |
| D | 용량·부위 표기 없음 | 비교하되 확인 | 묶음은 용량을 정했는데 상품명엔 용량이 없음 |
| E | 조건부 가격 | 비교하되 확인 | 체험가·한정가·첫 방문·요일·시간 |
| F | 묶음 상품 | 참고만 | 다른 시술이 '+'로 함께 들어감(진정관리·크라이오셀 같은 무료 추가는 제외) |
| G | 이용권·코스 | 참고만 | 무제한·기간 이용권·N주 프로그램 |
| H | 추가 옵션 | 참고만 | '옵션N)', '추가', '단독 불가' |
| I | 고시 가격표 | 비교하되 확인 | 비급여 진료비 고시표(정가) |
| J | 이름만 비슷한 다른 시술 | 비교 안 함 | 제품군 낱말은 있지만 어느 비교 묶음에도 넣지 않은 이름. **자동 병합하지 않고** 검토 대기열로만 |
| R | 확인 필요(NEEDS_REVIEW) | 비교하되 확인 | 같은 묶음 중간값(회당)의 1/10 이하 또는 10배 이상. 체험가·한정가가 아래로 먼 것은 행사라 R이 아니라 E |

## 4. 제품·장비가 섞인 묶음
- 한 묶음에 제품·장비가 둘 이상이면 가격 요약 위에 안내를 띄워요. 제품이 적힌 곳과 안 적힌 곳이 섞여 있어도 마찬가지예요.
- 지점 목록에는 '제품·장비' 칩이 붙어요: 전체 / 제품별 / 표기 없음, 숫자는 파는 지점 수.
- 칩을 누르면 그 제품을 적은 줄만으로 지점별 가격을 다시 골라요(`prodRank`). 줄마다 제품 표시가 붙어요.
- 지금 섞인 묶음은 51개예요(대기열 C).
  - 직접 만든 묶음: X03 스킨보톡스(보툴렉스·리즈톡스·나보타가 몇 줄), X10 수입 필러(벨로테로·레스틸렌·쥬비덤 — 묶음 이름부터 세 제품을 함께 비교), X28·X30·X35
  - 나머지는 자동 묶음

## 5. 바뀐 비교 묶음 ID의 처리
분류 규칙을 고치면 자동 묶음 ID가 바뀌어요. 이렇게 처리해요(`PRODUCT_AUDIT.md` F-06·F-07).
- **ID 연결표 `meta.keymap`**: 옛 ID를 새 ID에 이어요. 이번엔 396개 중 328개를 이었고, 이어지지 않는 68개는 옛 이름으로 보여줘요.
- **다시 묶인 ID 목록 `meta.recl`**: 이번에 337개예요. 이 묶음들은 다음처럼 다뤄요.
  - 가격 변동·검토 대기에서 빼요.
  - 가격 이력은 이날부터 다시 그려요.
  - 알림은 알리지 않고 기준만 다시 잡아요.
- 이 기기의 장바구니·관심·알림·저장한 비교는 앱을 열 때 새 ID로 옮겨요. 지우는 항목은 없어요.
