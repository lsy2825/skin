# 운영 비용 대시보드

## 1. 두 곳

| 위치 | 데이터 | 상태 |
|---|---|---|
| 앱 내정보 → 운영 현황 → '크레딧 단위 경제성' 카드 | `app/domain/economics.js` 가정값 | 동작(시연), '가정' 표시(e2e C24) |
| 서버 `GET /v1/admin/economics?from=&to=` (MFA 관리자) | `commerce_economics` = DB 실측 합계 | 코드·테스트 완료(api 10), 배포 전 |

## 2. 서버 실측 항목 (commerce_economics)

- `revenue`: 채널별 지급 완료 주문 수·총액(부가세 포함 결제액).
- `refunds`: 건수·금액·회수 크레딧·회수 못 한 크레딧.
- `credits`: 원장 유형×버킷별 합계(지급·보너스·예약·차감·반환·환불·조정).
- `features`: 기능별 작업 수·성공·반환·차감 크레딧(실패율을 볼 수 있음).
- `ai`: 호출 수·비용(원)·**가격표 없는 호출 수**·대체 호출 수·실패 호출 수. `ai_by_feature`: 기능별 AI 비용.
- `service_costs`: ACTUAL / BUDGET을 따로.

## 3. 모델 비용표 (model_cost_config)

공급자·모델·적용일·입력/캐시 입력/출력 백만 토큰당 단가·이미지 비용 계산 방법·통화·환율·출처·마지막 확인일. 호출 비용 = ((입력−캐시)×입력단가 + 캐시×캐시단가 + 출력×출력단가) ÷ 1,000,000 × 환율. 호출 날짜에 적용되는 행을 써요(가격이 바뀌어도 과거 비용이 바뀌지 않음). **지금 실제 단가는 넣지 않았어요** — 공급자 가격 페이지를 확인한 값만 넣어야 하고, 테스트는 '테스트용(실제 가격 아님)' 행만 써요.

## 4. 볼 때 기준

- 기능별 남는 돈 = 차감 크레딧 × 크레딧당 순수익 − AI 비용 − 배분한 서비스 비용.
- 가격표 없는 호출이 0보다 크면 비용이 과소 집계된 것이에요(먼저 비용표를 채워요).
- 반환(실패) 비율이 높은 기능은 사용자 경험·비용 모두 나빠요(AI 실패는 비용만 들고 매출 0).
