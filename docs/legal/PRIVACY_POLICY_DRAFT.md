## 1. 익명 이용 집계 — 사실 (약속 2)

| 항목 | 내용 |
|---|---|
| 보내는 것 | 단계 이름 **하나**(`{"s":"단계이름"}`). 단계는 8개뿐: `open`(앱 열기), `first_price`(처음 가격 봄), `compare_open`(비교 화면), `keep_cart`(담기), `keep_fav`(관심), `keep_alert`(알림 만듦), `cart_open`(장바구니 화면), `return_7d`(7일 안 재방문) |
| 보내는 방법·때 | 브라우저 `navigator.sendBeacon` → Cloudflare Worker `cf/metrics`(A). 같은 단계는 **한 기기에서 하루 한 번만** |
| 안 보내는 것 | 날짜·시각(서버가 받은 날짜로만 셈), 기기 식별자, 쿠키, 계정, 검색어·시술 이름·가격·장바구니·관심 목록·위치. `return_7d`는 폰에 저장한 지난 방문일로 **폰에서 판단**하고 날짜는 보내지 않음 |
| 서버에 남는 것 | **날짜별·단계별 횟수**만(기간 없이 통계 목적 보관, §0-3). IP·기기 정보·쿠키는 저장하지 않음(모르는 단계 이름은 거부). 합계 조회(`GET /v1/m/daily`)는 관리자(Access)만 |
| 네트워크에서 생기는 것 | 요청이 Cloudflare에 닿을 때 IP 등 접속 정보가 전송됨(저장은 안 함). Cloudflare 플랫폼 기본 로그는 `docs/DATA_AND_LEGAL.md` §5 '오류·사용 로그' 행과 같은 취급 — 검토 필요 |
| 폰에 남는 것 | 기록 하나(`pc:metrics`): 마지막 사용일(한국 시간)과 그날 보낸 단계 이름 — '하루 한 번'과 `return_7d` 판단에 씀. 끄기 설정(`pc:metricsOff`, 휴대폰 단위·계정과 무관). 이미 있던 것: 방문 횟수(`pc:visits`), 이번 탭 집계 표시(`pc:counted`) — 폰 안에서만(B #27) |
| 끄는 곳 | 마이 → 내 설정 **'익명 이용 집계 보내기'**, 기본 켜짐. 끄면 이 휴대폰에서는 새로 저장하는 것도 보내는 것도 없음(그날 기록 하나는 남겨, 같은 날 다시 켜도 두 번 세지 않음). 저장소가 막힌 폰에서는 그 화면을 닫기 전까지만 꺼짐이 유지됨(화면에 그렇게 안내). 다시 켜면 그때부터 보냄. 운영 설정(`metrics`)이 꺼져 있으면 스위치도 안 보임(B #27) |
| 켜는 조건 | `app/config.js`의 `metrics`는 기본 꺼짐. 이 초안을 사용자가 검토·승인하고 A4 주소가 생긴 뒤 B가 켬 |
| 광고·분석 SDK | 없음(코드 검색, CSP `connect-src`). 외부 분석 서비스에 보내지 않음 |

## 2. 푸시 알림 — 사실 (약속 1 + 5.0 설계 §3)

| 항목 | 내용 |
|---|---|
| 구독할 때 앱이 보내는 것 | ① 브라우저가 만든 **푸시 구독 정보**(푸시 서비스 주소 `endpoint`, 암호화 키 `p256dh`·`auth`). **서버는 암호화 키를 받지만 모양만 검사하고 버려요 — 저장하지 않아요**(푸시 본문이 비어 있어 암호화가 필요 없음) ② **알림 조건 최대 20개**: 종류(`target` 목표가 이하 · `watch` 가격 바뀜 · `newmatch` 파는 지점 늘어남 · `expiring` 행사 3일 남음), 시술 비교 키(예 `X24`), 목표가(`max`, 선택), 지역(`region`, 선택 — 지역 이름이지 위치 좌표가 아님) |
| 서버가 돌려주는 것 | 무작위 구독 `id`(22자). **폰에만** 저장 |
| 서버가 보관하는 것 | **알림 주소(`endpoint`)와 알림 조건**. 그 밖에 가입자 단위의 전달 기록(사람 정보 아님): 마지막으로 묶음 알림을 보낸 날, 마지막으로 마감 알림을 보낸 날, '보낼 소식 있음' 표시, 이미 알린 (시술·지역·종료일) 목록, 연속 전달 실패 횟수, 보내는 동안만 있는 처리 중 표시. *(A: '마지막으로 앱이 쓴 날'(`touched_day`)은 최종본에서 뺄 예정 — 뺀 뒤 최종 목록을 A가 다시 보냄)* |
| 접속 정보(IP) | 구독·규칙 요청의 IP(IPv6는 앞 64비트까지)는 '같은 곳에서 너무 자주 구독하는 것'을 막는 Cloudflare 내부 카운터의 열쇠로 **잠깐만** 쓰이고, 우리 D1·로그에는 저장하지 않아요. Cloudflare 플랫폼 기본 로그는 §1과 같은 취급 — 검토 필요 |
| 안 보내는 것 | 이름·연락처·계정, 장바구니·관심 목록 전체(조건만 감), 위치 좌표, 기기 정보, 검색어 |
| 알림 내용 | **본문 없음**(빈 푸시). 폰의 서비스 워커가 고정 문구("관심 시술 가격이 바뀌었어요")를 띄우고, 누르면 관심 탭(`#saved`)이 열림 → 푸시 서비스는 어떤 시술인지 모름. **광고 푸시 없음** |
| 보내는 때 | 가격 공장이 배포를 마친 뒤(가격은 주 1회 + 행사 종료 다음 날 수집 — '실시간' 아님). **08:00~21:00 한국 시간만**(발송은 20:45까지, 만료도 21시 전), 한 사람에게 **주 1회 묶음**, **행사 마감 임박(`expiring`)은 종료일마다 따로·하루 1번**(A 코드 확인) |
| 거쳐 가는 곳 | 푸시 구독 주소는 브라우저 제공업체의 푸시 서비스(Google FCM·Apple·Mozilla·Windows만 허용, 5.0 설계 §3) → **국외 사업자**. 저장은 Cloudflare D1(A). 위치: **아시아·태평양 = 국외**(A 확인, §0-5). *Cloudflare 문서: 위치 힌트(`apac`)는 '가장 가까운 곳에 두려는 시도'이지 보장이 아니고, 위치를 보장하는 '관할(jurisdiction)'은 `eu`·`us`·`fedramp`뿐이에요 → 처리방침에는 '한국 밖(주로 아시아·태평양)'으로 적어요* |
| 끄면 | 앱이 `DELETE /v1/push/subscribe/{id}`로 서버의 구독·조건을 지우는 때(B #28): ① '가격 알림 끄기'를 누를 때 — **바로** ② 마지막 가격 알림을 지워 조건이 0개가 될 때(남은 알림이 모두 앱 안에서만 알리는 종류일 때 포함) — 되돌리기 시간(6초)이 지난 뒤 ③ 앱을 열었을 때 브라우저 알림 권한이 꺼져 있거나 브라우저 구독이 사라졌거나 알림이 하나도 없을 때. 지운 뒤 브라우저 구독도 해지하고 폰의 id를 지움. 브라우저 설정에서 권한만 끄고 앱을 열지 않으면 앱은 알 수 없음 → 서버가 푸시 서비스의 404/410 응답으로 지우는 길만 남음(A 코드 확인). **서버가 지우는 때**(앱과 별개): 푸시 서비스가 404/410을 줄 때 바로, 그리고 **계속 전달에 실패할 때** — 푸시 서비스가 401/403을 3번, 네트워크 오류·5xx를 10번, 한 번도 푸시를 받지 못한 구독은 3번 실패하면 삭제(A 코드 확인). 알림이 하나도 없으면 '가격 알림 받기' 버튼이 없어 빈 구독은 만들어지지 않음 |
| 보관 기간 | 기간 없음 — 위 '끄면'의 경우에 바로 삭제(목적을 다하면 파기, 사용자 결정 §0-1). '365일 안 쓰면 삭제'·'꽉 찼을 때 오래된 것 밀어내기'는 두지 않음(A 확인) |
| 지운 뒤 | '바로 지워요'는 **운영 DB 기준**이에요. Cloudflare D1은 지정 시점으로 되돌리는 복구 기능(Time Travel)이 있어, 지운 행이 그 기간 동안 복구 가능한 형태로 남을 수 있어요. **그 기간은 확인하지 못했어요(Not certain)** — A가 계정에서 확인해 알려 줌 → §5-2 |
| 폰에 남는 것 | 구독 `id`(서버 구독을 지우면 함께 지움), 알림 조건(관심 탭의 알림 목록 `alerts`), 알림 켬/끔 상태 |

## 3. 처리방침에 넣을 문장 (확정 2026-10-15 — 법률 검토 전, B가 그대로)

### 3-1. 이용 집계 (B5)
> **윤실장이 어떻게 쓰이는지 세기**
> 앱이 잘 쓰이는지 보려고 '앱을 열었다', '가격을 봤다', '담았다' 같은 단계 이름 하나만 하루 한 번 보내요. 누가 보냈는지는 받지 않아요. 이름·계정·기기 번호·쿠키·검색어·가격·위치는 보내지 않고, 서버에는 날짜별·단계별 횟수만 남아요. 외부 분석 회사에는 보내지 않아요.
> 이 횟수는 누구의 것인지 알 수 없는 합계라서, 통계 목적으로 보관해요. 집계를 받는 서버는 한국 밖(주로 아시아·태평양 지역)의 Cloudflare 서버예요.
> 처음에는 켜져 있고, 마이 → 내 설정의 '익명 이용 집계 보내기'에서 끌 수 있어요. 끄면 이 휴대폰에서는 보내지 않아요. 휴대폰에는 마지막으로 쓴 날짜와 그날 보낸 단계 이름만 남아요(하루 한 번만 보내기 위해서예요).

### 3-2. 가격 알림 (B6)
> **관심 시술 가격 알림(푸시)**
> 알림을 켜면 ① 브라우저가 만든 알림 주소와 ② 어떤 시술을 어떤 조건(목표가·지역)으로 지켜볼지, ③ 알림을 마지막으로 보낸 날 같은 전달 기록이 윤실장 서버에 저장돼요. 이름·연락처·위치·장바구니는 저장하지 않아요.
> 알림은 새 가격을 모은 뒤 보통 주 1회 묶어서 보내고, 행사 마감이 임박한 알림만 따로 보내요. 오전 8시~오후 9시 사이에만 보내요.
> 알림 자체에는 내용이 없어서, 알림을 전달하는 브라우저 회사(Google·Apple 등)는 어떤 시술인지 알 수 없어요. 알림 주소와 조건을 저장하는 서버는 한국 밖(주로 아시아·태평양 지역)의 Cloudflare 서버예요. 광고 알림은 보내지 않아요.
> 알림 주소와 조건은 알림에 쓰는 동안만 두고, 다음 때 바로 지워요: 앱에서 알림을 끌 때, 가격 알림을 모두 지웠을 때(되돌리기 시간이 지나면), 앱을 열었는데 휴대폰 알림 권한이 꺼져 있거나 알림 구독이 사라졌을 때, 알림 서비스가 이 휴대폰에 더는 전달할 수 없다고 알려 올 때, 전달이 계속 실패할 때.

## 4. 화면 문구 (확정 2026-10-15 — B가 그대로, 줄여야 하면 C에게)

- **집계 칸(설정 스위치 옆):** B #27의 지금 문장 '앱을 쓴 단계 이름만 서버로 보내요(날짜·기기·위치·검색어 없음). 끄면 이 휴대폰에서는 보내지 않아요.'를 아래로 바꿔 주세요. 서버는 받은 날짜로 횟수를 세므로 '날짜 없음'이 '날짜도 남지 않는다'로 읽힐 수 있어요.
  > 앱을 쓴 단계 이름만 하루 한 번 서버로 보내요(기기·위치·검색어는 보내지 않아요). 끄면 이 휴대폰에서는 보내지 않아요.
- **푸시 칸:** B의 지금 문장 '일주일에 한 번 묶어서(행사 마감 임박은 따로), 오전 8시~오후 9시에만 와요.'는 매주 온다고 읽히고 시간대가 아직 정해지지 않았어요. 아래로 바꿔 주세요.
  > 가격이 바뀌면 보통 일주일에 한 번 묶어서 와요(행사 마감 임박은 따로).
  > 오전 8시~오후 9시에만 보내요.
