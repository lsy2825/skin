## 1. 익명 이용 집계 — 사실 (약속 2)

| 항목 | 내용 |
|---|---|
| 보내는 것 | 단계 이름 **하나**(`{"s":"단계이름"}`). 단계는 8개뿐: `open`(앱 열기), `first_price`(처음 가격 봄), `compare_open`(비교 화면), `keep_cart`(담기), `keep_fav`(관심), `keep_alert`(알림 만듦), `cart_open`(장바구니 화면), `return_7d`(7일 안 재방문) |
| 보내는 방법·때 | 브라우저 `navigator.sendBeacon` → Cloudflare Worker `cf/metrics`(A). 같은 단계는 **한 기기에서 하루 한 번만** |
| 안 보내는 것 | 날짜·시각(서버가 받은 날짜로만 셈), 기기 식별자, 쿠키, 계정, 검색어·시술 이름·가격·장바구니·관심 목록·위치. `return_7d`는 폰에 저장한 지난 방문일로 **폰에서 판단**하고 날짜는 보내지 않음 |
| 서버에 남는 것 | **날짜별·단계별 횟수**만. IP·기기 정보·쿠키는 저장하지 않음(모르는 단계 이름은 거부). 합계 조회(`GET /v1/m/daily`)는 관리자(Access)만 |
| 네트워크에서 생기는 것 | 요청이 Cloudflare에 닿을 때 IP 등 접속 정보가 전송됨(저장은 안 함). Cloudflare 플랫폼 기본 로그는 `docs/DATA_AND_LEGAL.md` §5 '오류·사용 로그' 행과 같은 취급 — 검토 필요 |
| 폰에 남는 것 | 기록 하나(`pc:metrics`): 마지막 사용일(한국 시간)과 그날 보낸 단계 이름 — '하루 한 번'과 `return_7d` 판단에 씀. 끄기 설정(`pc:metricsOff`, 휴대폰 단위·계정과 무관). 이미 있던 것: 방문 횟수(`pc:visits`), 이번 탭 집계 표시(`pc:counted`) — 폰 안에서만(B #27) |
| 끄는 곳 | 마이 → 내 설정 **'익명 이용 집계 보내기'**, 기본 켜짐. 끄면 이 휴대폰에서는 새로 저장하는 것도 보내는 것도 없음(그날 기록 하나는 남겨, 같은 날 다시 켜도 두 번 세지 않음). 저장소가 막힌 폰에서는 그 화면을 닫기 전까지만 꺼짐이 유지됨(화면에 그렇게 안내). 다시 켜면 그때부터 보냄. 운영 설정(`metrics`)이 꺼져 있으면 스위치도 안 보임(B #27) |
| 켜는 조건 | `app/config.js`의 `metrics`는 기본 꺼짐. 이 초안을 사용자가 검토·승인하고 A4 주소가 생긴 뒤 B가 켬 |
| 광고·분석 SDK | 없음(코드 검색, CSP `connect-src`). 외부 분석 서비스에 보내지 않음 |

## 2. 푸시 알림 — 사실 (약속 1 + 5.0 설계 §3)

| 항목 | 내용 |
|---|---|
| 구독할 때 서버에 보내는 것 | ① 브라우저가 만든 **푸시 구독 정보**(푸시 서비스 주소 `endpoint`, 암호화 키 `p256dh`·`auth`) ② **알림 조건 최대 20개**: 종류(`target` 목표가 이하 · `watch` 가격 바뀜 · `newmatch` 파는 지점 늘어남 · `expiring` 행사 3일 남음), 시술 비교 키(예 `X24`), 목표가(`max`, 선택), 지역(`region`, 선택 — 지역 이름이지 위치 좌표가 아님) |
| 서버가 돌려주는 것 | 무작위 구독 `id`. **폰에만** 저장(서버는 id와 구독 정보·조건을 함께 보관) |
| 안 보내는 것 | 이름·연락처·계정, 장바구니·관심 목록 전체(조건만 감), 위치 좌표, 기기 정보, 검색어 |
| 알림 내용 | **본문 없음**(빈 푸시). 폰의 서비스 워커가 고정 문구("관심 시술 가격이 바뀌었어요")를 띄우고, 누르면 관심 탭(`#saved`)이 열림 → 푸시 서비스는 어떤 시술인지 모름. **광고 푸시 없음** |
| 보내는 때 | 가격 공장이 배포를 마친 뒤(가격은 주 1회 + 행사 종료 다음 날 수집 — '실시간' 아님). **오전 8시~오후 9시(한국 시간)**, 한 사람에게 **주 1회 묶음**, **행사 마감 임박(`expiring`)만 따로** (§0-4 확인 필요) |
| 거쳐 가는 곳 | 푸시 구독 주소는 브라우저 제공업체의 푸시 서비스(Google FCM·Apple·Mozilla·Windows만 허용, 5.0 설계 §3) → **국외 사업자**. 저장은 Cloudflare D1(A). 위치(국내/국외)는 A에게 확인 |
| 끄면 | 앱이 `DELETE /v1/push/subscribe/{id}`로 서버의 구독·조건을 지우는 때(B #28): ① '가격 알림 끄기'를 누를 때 — **바로** ② 마지막 가격 알림을 지워 조건이 0개가 될 때(남은 알림이 모두 앱 안에서만 알리는 종류일 때 포함) — 되돌리기 시간(6초)이 지난 뒤 ③ 앱을 열었을 때 브라우저 알림 권한이 꺼져 있거나 브라우저 구독이 사라졌거나 알림이 하나도 없을 때. 지운 뒤 브라우저 구독도 해지하고 폰의 id를 지움. 브라우저 설정에서 권한만 끄고 앱을 열지 않으면 앱은 알 수 없음 → 서버가 푸시 서비스의 404/410 응답으로 지우는 길만 남음(A 구현 확인 필요, 5.0 설계 §3). 알림이 하나도 없으면 '가격 알림 받기' 버튼이 없어 빈 구독은 만들어지지 않음 |
| 보관 기간 | **가격 알림이 하나 이상 있는 동안**(사용자 결정 §0-1 일부). 'N개월 안 쓰면 삭제'는 결정 전 |
| 폰에 남는 것 | 구독 `id`(서버 구독을 지우면 함께 지움), 알림 조건(관심 탭의 알림 목록 `alerts`), 알림 켬/끔 상태 |

## 3. 처리방침에 넣을 문장 (초안, 해요체 — 검토 뒤 B가 그대로)

### 3-1. 이용 집계 (B5)
> **윤실장이 어떻게 쓰이는지 세기**
> 앱이 잘 쓰이는지 보려고 '앱을 열었다', '가격을 봤다', '담았다' 같은 **단계 이름 하나**만 하루 한 번 보내요. 누가 보냈는지는 받지 않아요 — 이름·계정·기기 번호·쿠키·검색어·가격·위치는 보내지 않고, 서버에는 날짜별 횟수만 남아요. 외부 분석 회사에 보내지 않아요.
> 처음에는 켜져 있고, 마이 → 내 설정의 '익명 이용 집계 보내기'에서 끌 수 있어요. 끄면 이 휴대폰에서는 보내지 않아요. 휴대폰에는 마지막으로 쓴 날짜와 그날 보낸 단계 이름만 남아요(하루 한 번만 보내기 위해서예요).

### 3-2. 가격 알림 (B6)
> **관심 시술 가격 알림(푸시)**
> 알림을 켜면 ① 브라우저가 만든 알림 주소(푸시 구독 정보)와 ② 어떤 시술을 어떤 조건(목표가·지역)으로 지켜볼지가 윤실장 서버에 저장돼요. 이름·연락처·위치·장바구니는 저장하지 않아요.
> 알림은 새 가격을 모은 뒤 **오전 8시~오후 9시 사이에, 보통 주 1회 묶어서** 보내고, 행사 마감이 임박한 알림만 따로 보내요. 알림 자체에는 내용이 없어서, 알림을 전달하는 브라우저 회사(Google·Apple 등)는 어떤 시술인지 알 수 없어요. 광고 알림은 보내지 않아요.
> 알림 주소와 조건은 **가격 알림이 하나 이상 있는 동안만** 보관해요(§0-1의 'N개월'을 정하면: 또 __개월 동안 앱을 쓰지 않으면 지워요). '가격 알림 끄기'를 누르면 바로, 마지막 가격 알림을 지우면 잠시 뒤(되돌리기 시간이 끝나면) 서버에서 지워요. 브라우저 설정에서 알림을 껐다면 앱을 다시 열 때 지워요. (A 확인 뒤 덧붙임: 앱을 열지 않아도 알림이 전달되지 않는 것이 확인되면 서버가 지워요.)

## 4. 화면 문구 (B가 그대로 — 줄여야 하면 C에게)

- **'주 1회·8~21시' 사용 가능 여부:** 가능해요. 다만 그대로 쓰면 두 군데가 틀려요. 마감 임박 알림은 묶음과 **따로** 가고, 시간대는 §0-4 확인 뒤에 확정해요. 정확한 한 줄:
  > 새 가격을 모은 뒤 오전 8시~오후 9시 사이에 보내요. 보통 주 1회 묶어서, 행사 마감이 임박한 알림만 따로 와요.
- **알림 설정 화면 설명(해요체):**
  > 알림을 켜면 알림 주소와 지켜볼 조건만 서버에 저장돼요. 이름·연락처·위치는 저장하지 않아요. 끄거나 가격 알림을 모두 지우면 서버에서도 지워요.
- **푸시 칸(B가 이미 쓴 문장 검토):** '일주일에 한 번 묶어서(행사 마감 임박은 따로), 오전 8시~오후 9시에만 와요.' — 두 군데를 고치길 권해요. ① 알림은 **가격이 바뀌었을 때만** 가므로 '일주일에 한 번'은 '매주 온다'로 읽힐 수 있어요 → '보통 일주일에 한 번'. ② 시간대는 §0-4(A 확인) 전이라 아직 확정 아님. 바꾼다면:
  > 가격이 바뀌면 보통 일주일에 한 번 묶어서 와요(행사 마감 임박은 따로). 오전 8시~오후 9시에만 보내요. ← 마지막 문장은 §0-4 확정 뒤
- **죠미 도움말 '알림' 답(B가 푸시를 켤 때 `app/domain/jomichat.js`의 alert 답을 바꿀 문장):** 지금 답은 '시술을 관심에 저장하면, 앱을 열 때 모은 가격이 내려간 곳이 있으면 알려 드려요(이 기기 안에서).' 푸시가 켜진 뒤:
  > 시술에 가격 알림을 만들면 새 가격이 들어온 뒤 내려간 곳을 알려 드려요. 휴대폰 알림을 켜 두면 앱을 열지 않아도 와요(보통 주 1회 묶어서, 행사 마감 임박은 따로).
  (도움말 답이라 해요체·병원 이름·가격 없음. 시간대는 §0-4 뒤에 덧붙일지 정해요. 바꾼 뒤 `node tools/jomi_chat_eval.js`·`tests/jomichat.test.js`는 B가 돌려요.)
- **익명 집계 스위치 안내(B #27의 한 줄 검토):** 지금 문장 '앱을 쓴 단계 이름만 서버로 보내요(날짜·기기·위치·검색어 없음). 끄면 이 휴대폰에서는 보내지 않아요.'는 사실과 맞아요. 다만 서버는 받은 날짜로 횟수를 세므로 '날짜 없음'이 '날짜도 남지 않는다'로 읽힐 수 있어요. 바꾼다면:
  > 앱을 쓴 단계 이름만 하루 한 번 서버로 보내요(기기·위치·검색어는 보내지 않아요). 끄면 이 휴대폰에서는 보내지 않아요.
- **죠미 도움말(반말, 60자 이하, 금액·%·병원 이름·의학 단어·해요체 없음 — `tests/jomilines.test.js` 규칙으로 확인):**
  1. 관심 시술 가격이 바뀌면 알려 줄게. 새 가격이 들어온 뒤에만 보내.
  2. 알림은 낮 시간에 보통 주 1회 묶어서 가. 급한 마감 소식만 따로야.
  3. 알림을 끄면 저장해 둔 조건도 바로 지워. 광고는 안 보내.

## 5. 변호사에게 물을 질문 (검토 필요 — `docs/LEGAL_REVIEW_CHECKLIST.md` D6~D8과 같음)

1. 날짜별·단계별 **횟수 합계만** 남기는 익명 집계(개인 식별자·IP·쿠키 저장 없음)가 개인정보 처리에 해당하나요? 처리방침 기재·동의·보관 기간 문장이 필요한가요? 요청이 닿을 때 Cloudflare에 전송되는 IP는 어떻게 적어야 하나요? **기본 켜짐 + 설정에서 끄기**(사용자 결정 §0-2)로 충분한가요, 처음에 묻고 켜야 하나요?
2. 푸시 구독 정보(푸시 서비스 주소·암호화 키)와 알림 조건(시술 비교 키·목표가·지역)은 개인정보인가요? 시술 이름이 든 조건이 **민감정보(건강)** 로 읽힐 수 있나요? 필요한 동의 방식(알림 켤 때의 안내로 충분한지)은요? 보관 기간을 '가격 알림이 하나 이상 있는 동안'(기간 제한 없음)으로만 적어도 되나요, 'N개월 미사용 시 삭제' 같은 기간이 필요한가요(§0-1 남은 결정)?
3. 푸시가 브라우저 제공업체의 푸시 서비스(국외)를 거치고 저장이 Cloudflare에 있을 때 **국외 이전·처리 위탁 고지**가 필요한가요? 본문이 빈 푸시(시술 정보 없음)라는 점이 판단을 바꾸나요?
4. 광고가 아닌 가격 변동 알림을 **오전 8시~오후 9시**에만 보내는 것으로 정보통신망법의 야간 전송 제한(광고성 정보, 오후 9시~오전 8시 — 확인 필요)과 무관하다고 봐도 되나요? '관심 시술 가격이 바뀌었어요' 같은 문구가 광고성 정보로 읽힐 여지는요?
