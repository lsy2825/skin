## 1. 익명 이용 집계 — 사실 (약속 2)

| 항목 | 내용 |
|---|---|
| 보내는 것 | 단계 이름 **하나**(`{"s":"단계이름"}`). 단계는 8개뿐: `open`(앱 열기), `first_price`(처음 가격 봄), `compare_open`(비교 화면), `keep_cart`(담기), `keep_fav`(관심), `keep_alert`(알림 만듦), `cart_open`(장바구니 화면), `return_7d`(다시 옴 — 이 브라우저가 마지막으로 집계를 보낸 날이 1~7일 전일 때만) |
| 보내는 방법·때 | 브라우저 `navigator.sendBeacon` → Cloudflare Worker `cf/metrics`(A). 같은 단계는 **한 휴대폰(브라우저)에서 하루 한 번만**(하루는 한국 시간 자정 기준). 그날 처음 쓸 때 `open`을 보내요 |
| 안 보내는 것 | 날짜·시각(서버가 받은 날짜로만 셈), 기기 식별자, 쿠키, 계정, 검색어·시술 이름·가격·장바구니·관심 목록·위치. `return_7d`는 이 브라우저에 남긴 마지막 집계 날짜(켜진 상태에서 마지막으로 보낸 날)가 **1~7일 전일 때만** 그날 첫 단계와 함께(`open`보다 먼저) 보내요. 기록이 없는 브라우저(처음 쓰거나, 시크릿 창·다른 브라우저·데이터 삭제 뒤), 같은 날, 8일 이상 지난 때, 기록된 날이 휴대폰 날짜보다 뒤일 때는 보내지 않아요. 집계를 꺼 둔 동안 쓴 날은 치지 않고, 탭을 연 채 자정을 넘기면 다음 날로 세요. 판단은 **폰에서** 하고 날짜는 보내지 않음(`app/domain/metrics.js` `opening`) |
| 세는 방법의 한계 | 서버는 누가 보냈는지 읽거나 남기지 않아서 **같은 사람을 가려내지 못해요**. '하루 한 번'은 브라우저에 남긴 기록(`pc:metrics`)으로만 지켜져요 → 시크릿 창, 앱(사이트) 데이터 삭제, 다른 브라우저·다른 폰, 저장소가 막힌 폰(화면을 새로 열 때마다), 저장소가 가득 찬 폰(새로 열 때마다, `return_7d` 포함), 휴대폰 시계를 바꾼 때에는 같은 날 다시 세요. 반대로 브라우저가 보내기로 받아들였지만 서버에 닿지 못했거나 거부된 것(연결 끊김, 403·503)은 다시 보내지 않아 빠져요. 서버는 보낸 곳 표시(`Origin`)만 보고 받아서 앱 밖에서 꾸민 요청도 세고, 단계마다 하루 5,000에서 더 늘지 않아요(`cf/metrics` `STAGE_DAILY_CAP`). 그래서 합계는 '사람 수'가 아니라 대략의 '보낸 횟수'예요(A 메모, B 2026-10-16) |
| 서버에 남는 것 | **날짜별·단계별 횟수**만(기간 없이 통계 목적 보관, §0-3). IP·기기 정보·쿠키는 저장하지 않음(모르는 단계 이름은 거부). 합계 조회(`GET /v1/m/daily`)는 관리자(Access)만. Worker는 받을 때마다 횟수를 바로 1 더해서, D1 자동 복구 기록(Time Travel, 무료 플랜 7일 — §2 '지운 뒤'와 같음, Not certain)으로는 횟수가 바뀐 시각(분 단위)을 볼 수 있어요. 보낸 사람은 남지 않아요 — 처리방침에 적을지 §5-1 검토 필요 |
| 네트워크에서 생기는 것 | 요청이 Cloudflare에 닿을 때 IP 등 접속 정보가 전송됨(저장은 안 함). Cloudflare 플랫폼 기본 로그는 `docs/DATA_AND_LEGAL.md` §5 '오류·사용 로그' 행과 같은 취급 — 검토 필요 |
| 폰에 남는 것 | 기록 하나(`pc:metrics`): 마지막으로 집계를 보낸 날(한국 날짜)과 그날 보낸 단계 이름 — '하루 한 번'과 `return_7d` 판단에 씀. 끄기 설정(`pc:metricsOff`, 이 브라우저 저장소 단위·계정과 무관 — 시크릿 창·다른 브라우저·데이터 삭제 뒤에는 기본값인 켜짐). 이미 있던 것: 방문 횟수(`pc:visits`), 이번 탭 집계 표시(`pc:counted`) — 폰 안에서만(B #27) |
| 끄는 곳 | 마이 → 내 설정 **'익명 이용 집계 보내기'**, 기본 켜짐. 끄면 이 브라우저에서는 새로 저장하는 것도 보내는 것도 없음(그날 기록 하나는 남겨, 같은 날 다시 켜도 두 번 세지 않음). 시크릿 창·다른 브라우저에서 쓰거나 앱 데이터를 지우면 다시 켜진 상태(기본값)예요. 저장소가 막힌 폰에서는 그 화면을 닫기 전까지만 꺼짐이 유지됨(화면에 그렇게 안내). 다시 켜면 그때부터 보냄. 운영 설정(`metrics`)이 꺼져 있으면 스위치도 안 보임(B #27) |
| 켜는 조건 | `app/config.js`의 `metrics`는 기본 꺼짐. 이 초안을 사용자가 검토·승인하고 A4 주소가 생긴 뒤 B가 켬 |
| 광고·분석 SDK | 없음(코드 검색, CSP `connect-src`). 외부 분석 서비스에 보내지 않음 |

## 2. 푸시 알림 — 사실 (약속 1 + 5.0 설계 §3)

**A의 브랜치 platform/alerts-worker(6d2de49, 아직 main에 합쳐지지 않음) 코드와 2026-10-16에 대조 — 합쳐진 뒤 다시 대조.** 아래 `파일:줄`은 앞에 `app/`이 없으면 그 브랜치의 `cf/alerts/` 기준이고, `app/`으로 시작하는 것은 main의 앱 코드예요.

| 항목 | 내용 |
|---|---|
| 구독할 때 앱이 보내는 것 | ① 브라우저가 만든 **푸시 구독 정보**: 푸시 서비스 주소 `endpoint`, 암호화 키 `p256dh`·`auth`, 만료 시각 `expirationTime`(보통 비어 있음)(`app/domain/push.js:44-54`). 서버는 `endpoint`만 꺼내 저장하고, **암호화 키는 모양만 검사하고 버려요 — 저장하지 않아요**(푸시 본문이 비어 있어 암호화가 필요 없음). `expirationTime`은 읽지 않아요(`src/push.js:11-22`) ② **알림 조건 1~20개**(0개·21개 이상은 거절 — `src/rules.js:153`, `src/worker.js:112-113`): 종류(`target` 최저가가 목표가 이하로 내려옴 · `watch` 가격 바뀜(중간값 5% 이상 움직임 또는 새 최저가) · `newmatch` 파는 지점 늘어남 · `expiring` 행사가 3일 안에 끝남), 시술 비교 키(예 `X24` — `X`+두 자리 또는 `T`+일곱 자리), 목표가(`max` — `target`엔 꼭, `expiring`엔 선택, `watch`·`newmatch`엔 버림), 지역(`region`, 선택 — 시·도 17개 또는 `수도권`, 지역 이름이지 위치 좌표가 아님). 다른 칸이 끼어 있으면 거절(`src/rules.js:5-17`, `144-178`) |

| 구독과 이어지지 않는 서버 기록 | 누가 지켜보는지 없이 (시술 키, 지역) 쌍마다의 가격 숫자(최저가·지점 수·중간값·곧 끝나는 가격 — `snap`, 아무도 안 지켜보는 쌍은 지움 `src/sql.js:141`), 푸시 서비스마다의 서명 토큰(`vapid`, 12시간), 숫자 몇 개(`stat`: 지금 구독 수, 그날 새 구독 수 — 지난 날은 지움 `src/sql.js:142`, 마지막 공장 날짜)(`migrations/0001_init.sql:39-86`) |
