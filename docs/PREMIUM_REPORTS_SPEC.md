# 프리미엄 보고서 명세

원천: `app/domain/premium.js`(앱·서버 공용), 가격 맥락 `app/domain/pricectx.js`. 모든 숫자는 모은 가격에서 계산해요.

## 1. 공통 규칙

- **판매 전 점검(available)**: 데이터가 보고서를 뒷받침하지 못하면 예약하지 않고 이유를 보여줘요.
- **쓸 수 있는 결과(usable)**: 항목 0개·지점 0곳·계산 불가뿐인 보고서는 차감하지 않고 반환.
- 지점당 한 숫자: 한 지점의 여러 옵션 중 가장 낮은 '살아 있는' 가격(종료된 이벤트·급변 확인 중 제외).
- 비교 기준 표시: '병원 표시가(지점마다 가장 싼 가격), 지역', 데이터 날짜. 부가세 포함 광고 vs 별도 표시가 섞이면 안내.
- 병원 순위·추천을 만들지 않아요. 다시 열기는 무료, 삭제 가능.
- **공유 요약(share_summary)**: 묶음 이름·중간값·지점 수 등 공개 가능한 숫자만. 붙여 넣은 원문·사진·견적의 개인 가격은 넣지 않아요(테스트). 서버에서는 무작위 64자 토큰 링크, 앱 시연에서는 요약 글 복사.

## 2. 보고서 종류

| 기능 | 판매 조건 | 내용 |
|---|---|---|
| 이벤트 글·사진 읽기 | 가격 줄 1개 이상 | 항목별 매칭 상태, EXACT면 같은 묶음 최저·중간값·최고·지점 수와 판정(±10%: 낮음/비슷/높음, 3곳 미만은 '적음'), 확인 필요 사항 |
| 견적·패키지 읽기 | 가격 줄 1개 이상 | 위 + 패키지 구성별 매칭, 모든 구성이 EXACT일 때만 구성 중간값 합(참고). 원문은 보고서에만 |
| 이벤트 여러 개 비교 | 글 중 하나라도 가격 줄 | 이벤트 2~4개에서 정확히 같은 묶음끼리 나란히 + 시장 범위 |
| 제품 심층 비교 | 서로 다른 두 시술 | 전국·지역·브랜드별 지점 수·최저·중간값. 효과·통증 비교 안 함 |
| 지역 가격 보고서 | 지점 3곳 이상 지역이 2개 이상 | 지역별 지점 수·최저·중간값·최고, 3곳 미만 지역은 흔들릴 수 있다고 표시 |
| 가격 이력 보고서 | **주간 기록 4개 이상** | 실제로 모은 주만. 계절성·미래 가격 추정 안 함 |
| 종합 보고서 | 장바구니 또는 시술 | 계획 + 시술별 지역(+ 기록 4주 이상이면 이력) |

## 3. 가격 이력 — 지금 판매하지 않음

`data.json trend.dates`가 2개(2026-10-13, 10-14)뿐이라 모든 시술이 판매 조건(4주)을 못 넘어요. 그래서 이 기능을 누르면 "가격 기록이 2주뿐이에요. 4주 이상 모이면…"으로 차감 없이 안내해요(e2e C16). 가짜 이력을 만들지 않아요. 주간 수집이 쌓이면(빨라야 2026-11 초 — 추정) 자동으로 열려요.
