# 고급 사용자 편의 로드맵

기준: 2026-10-13. ADVANCED USER CONVENIENCE & UX POLISH 지시서의 7개 영역을 항목마다 정리했어요.
**작업 원칙**
- 지금 앱에 있는 기능을 먼저 확인했어요. 이미 있는 건 다시 만들지 않고, 쓰기 불편한 부분부터 고쳤어요.
- 모든 기능은 실제 데이터와 상태(주소·기기 저장소·장바구니 계산)에 연결돼 있어요. 목업은 없어요.
- 검사 결과는 `docs/UX_QA_REPORT.md`에 있어요. 실제로 돌린 것만 적었어요.

**우선순위 기준**
- **P0(출시 필수):** 가격을 찾고, 장바구니를 꾸리고, 결과를 저장·공유하는 기본 흐름에 꼭 필요한 것. 실수를 되돌릴 수 있어야 하고, 정보를 믿을 수 있어야 해요.
- **P1(출시 후 개선):** 있으면 확실히 편하지만 지금도 다른 방법으로 할 수 있는 것, 또는 외부 키·결정이 필요한 것.
- **P2(장기 고도화):** 서버, 통계, 법률 검토 같은 큰 전제가 필요한 것.

**상태 표시**
- 기존: 지시서 이전부터 있던 기능
- 신규: 이번에 만든 기능
- 부분: 일부만 됨
- 미구현 / BLOCKED: 아직 없거나, 키·결정을 기다리는 중

## 8. 화면이 복잡해지지 않게 한 결정
- 필터 칩, 내 필터, 용량 칩, 결과 없음 대안은 **해당할 때만** 나타나요. 조건이 없으면 자리를 차지하지 않아요.
- 복사·신고·즐겨찾기는 작은 보조 버튼이에요. 가격·순위 같은 주요 숫자보다 눈에 띄지 않게 했어요.
- 확인 창(`confirm`)을 늘리지 않고, 먼저 실행한 뒤 6초 동안 되돌릴 수 있게 했어요.
- 터치 영역은 넓혔지만 글자 크기와 줄 간격은 그대로예요. 정보 밀도를 유지했어요.

## 9. 다음 작업 (P1 → P2)
**P1: 출시 후 개선**
1. **시술별 속성 필터:**
   - 부위(이마·눈가·턱), 원산지(국산·수입), 제품(제오민·나보타 등)으로 걸러요.
   - 필요한 것: 상품명에서 이 속성을 뽑는 규칙과 테스트. `xkeys.py`처럼 오매칭을 막아야 해요.
2. **모바일 비교 카드:**
   - 한 시술을 지점 2~3곳 카드로 좌우로 넘겨 보기.
   - 지금 목록형도 넘침은 없어서 P1로 뒀어요.
3. **집·직장 주소 검색:**
   - 필요한 것: 지오코딩 서비스 선택. 키와 비용이 필요하고, 주소를 외부로 보내기 때문에 개인정보 검토도 필요해요.
   - 지금은 GPS나 지도 가운데로 정해요.
4. **이메일·푸시 가격 알림:** BLOCKED. Supabase와 메일 발송 키가 필요하고, 사용자 결정으로 미뤘어요.
5. **즐겨찾기·내 필터·장소 계정 동기화:** BLOCKED. 로그인 키가 필요해요. 장바구니 동기화 코드는 준비돼 있어요(`app/auth.js`).
6. **신고를 운영 큐로 받기:**
   - 지금은 GitHub 이슈나 복사예요.
   - 필요한 것: 서버 저장소(Supabase `user_reports` 테이블 설계 완료)와 관리자 인증.
7. **실기기·스크린리더 검사:** iPhone Safari, Android, VoiceOver, TalkBack(`UX_QA_REPORT.md` 6절).
8. **블리비 프라임 타임 시간대:** 사이트 문구를 모으기 시작했어요. 시각이 확인되면 방문 시간 필터에 반영해요.

**P2: 장기 고도화**
1. **실제 검색량 기반 인기 검색어:** 서버 집계와 개인정보 처리방침이 필요해요.
2. **이동 시간·교통비를 반영한 여러 지점 조합:** 마스터 요구사항에서도 후속 단계예요.
3. **3곳 이상 동시 지점 비교, 비교 결과 이미지 공유**
4. **기록 기반 추천:** 받은 시술 주기에 맞춘 알림. 민감정보라 동의와 처리방침이 먼저예요.
5. **SEO 공개 페이지:** 법률 검토 후 `publicIndex` 플래그로 켜요.
