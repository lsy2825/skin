# PWA 구현 (설치·업데이트·오프라인·알림 준비)

기준일: 2026-10-14. 코드: `app/manifest.webmanifest`, `app/sw.js`, `app/app.js`의 `installCard`·`deviceCard`·`notifyPanel`·서비스 워커 등록. 테스트: `tests/e2e/pricenow.js` S20·S22, `tests/e2e/data_sync.js`.

## 1. 구성
| 요소 | 상태 |
|---|---|
| 웹 앱 매니페스트 | `id: "./"`, 이름·짧은 이름·설명·`lang: ko`, `start_url: ./#home`, `scope: ./`, `display: standalone`, 배경·테마색, 아이콘 192·512·maskable 512, **바로가기 3개**(전체 가격표·장바구니·관심·알림) |
| 아이콘 | 원본 아이콘에서 만든 192/512/maskable, apple-touch-icon 180, favicon 32 (`brand/make_icons.py`) |
| 서비스 워커 | `pc-v14`. 앱 코드는 네트워크 우선(실패 시 사본), 그림·글꼴은 사본 우선, 지도 타일은 네트워크 우선. **가격 파일은 건드리지 않음**(앱이 검사한 사본을 따로 보관) |
| 업데이트 | 새 서비스 워커가 바로 활성화되면, 이전에 서비스 워커가 있던 경우에만 "앱이 새 버전으로 바뀌었어요 · 새로고침" 알림(첫 설치 때는 안 띄움) |
| 오프라인 | 앱 화면은 서비스 워커 사본으로 열리고, 가격은 앱의 검사된 사본 + "저장된 가격 정보입니다. 현재 가격과 다를 수 있습니다." |
| 죠미 로딩 | 첫 방문은 졸린 죠미 + 실제 진행률(%)·받은 MB. 다 받으면 바로 화면. 인위적인 대기 없음 |

## 2. 설치 안내 (데이터 상태·앱 설치 화면, `#data`)
| 환경 | 보이는 것 |
|---|---|
| 설치한 앱으로 실행 중 | "지금 설치한 앱으로 열려 있어요" |
| 브라우저가 설치를 허락(Chrome·Edge·Android, `beforeinstallprompt`) | '이 기기에 설치하기' 버튼 → 브라우저의 설치 창 |
| iPhone·iPad Safari | Safari 공유 → 홈 화면에 추가 → 추가, 설치 후 알림(iOS 16.4+) |
| 그 밖(허락 신호 없음) | "이 브라우저가 지금 설치 버튼을 주지 않았어요" + Android·PC·iPhone 방법 |

- **작동하지 않는 설치 버튼은 보여주지 않아요.** 버튼은 브라우저가 설치를 허락한 신호를 받았을 때만 나와요.
- 테스트에서 신호를 흉내 내어 버튼이 생기고, 누르면 브라우저의 설치 창이 호출되는지 확인해요.

## 3. 이 기기
- 앱으로 실행 중인지(예/아니요)
- 저장된 가격: 수집일·지점 수·줄 수·크기
- 데이터 버전
- 앱 버전(서비스 워커 캐시 이름)
- 이 사이트 저장 공간
- 휴대폰 알림 권한
- '저장된 가격 지우고 다시 받기': 진행 중인 받기를 멈추고 가격 사본만 지운 뒤 다시 열어요. 관심·장바구니·설정은 남아요.

## 4. 푸시 준비
- 지금은 앱을 열 때 찾은 변화만 휴대폰 알림으로 보여줘요(`registration.showNotification`). 권한은 사용자가 누를 때만 물어요.
- 테스트 알림은 TEST 표시를 붙여요.
- 백그라운드 푸시(앱이 닫혀 있을 때, 6.0 약속 1): **앱 쪽은 만들었고 꺼져 있어요**(B6). `config.js`의 `alertsApi`(A의 cf/alerts 주소)와
  `pushPublicKey`(VAPID 공개키)가 둘 다 있어야 관심 탭에 '가격 알림 받기'가 보여요. 비어 있으면 버튼·권한 요청·요청이 모두 0이에요(`tests/e2e/push.js`).
  1. 권한은 '가격 알림 받기'를 누른 뒤에만 물어요(iOS는 홈 화면에 설치한 앱, 16.4 이상).
  2. 구독: `POST {alertsApi}/v1/push/subscribe {subscription, rules}` → `{id}`(폰에만 저장, `pc:push`). 알림을 바꾸면 `PUT /v1/push/rules/{id}`,
     끄면 `DELETE /v1/push/subscribe/{id}`. 규칙은 폰의 가격 알림에서 만들어요(최대 20개, `app/domain/push.js`). 내 견적 합계·지점 상품
     목표가는 맞는 종류가 없어서 앱을 열 때만 알려요. '특가 포함'을 끄고 만든 알림(`sp === false`)도 이 기기에서만 알려요 — 서버 규칙은
     특가를 늘 넣어 계산해요(A, 2026-10-16). 시트·목록('일반가만 · 이 기기만')·패널에 그렇게 보여요.
     '끄기'의 DELETE는 보내기 **전에** 그 id를 폰(`pc:pushDel`, 최대 5개)에 적고, 서버가 끝난 답(2xx·4xx, 408·429 빼고)을 주면 지워요.
     닿지 않으면(오프라인·5xx·10초 넘게 답 없음·페이지를 떠남) 다음 시작에 다시 보내요. 지금 쓰는 id는 지우지 않아요.
  3. 서비스 워커: 내용 없는 푸시를 받으면 고정 문구 '관심 시술 가격이 바뀌었어요'를 띄우고, 누르면 관심 탭(#saved)을 열어요(`tests/sw.test.js`).
  4. 서버(발송·조용한 시간·주 1회 묶음·VAPID 비밀 키)는 A의 cf/alerts. 비밀 키는 저장소에 넣지 않아요.
  5. 실기기 확인(안드로이드 Chrome, iOS 설치 앱에서 실제 푸시·알림 누르기)은 A의 주소가 생긴 뒤에 해요.
  6. 처리방침 화면 `#privacy`: C의 `docs/legal/PRIVACY_POLICY_DRAFT.md` §3-1(익명 집계 — `metrics` 켜짐)·§3-2(푸시 — 위 두 값이 있을 때)를 켜진 것만 그대로 보여줘요. 둘 다 꺼져 있으면 들어가는 곳이 없고 `#privacy`는 마이 화면이에요. 알림 칸·내 설정 집계 칸 문장은 같은 문서 §4 그대로(`tests/e2e/privacy.js`).
